## What changed since 0.2.0

* **Code that logs nothing can leave out the logging dependencies.** With `underTest.logging = false`, the plugin adds neither the SLF4J API nor Log4j, so the project's published POM names no logging library ([record 0030](https://github.com/fiftiesHousewife/under-test-java-conventions/blob/main/docs/decisions/0030-code-that-logs-nothing-can-leave-out-the-logging-dependencies.md)).
* **A repo can run mutation testing in check.** With `underTest.mutationTestingInCheck = true`, `check` runs `pitest`, and with it a minimum mutation score ([record 0029](https://github.com/fiftiesHousewife/under-test-java-conventions/blob/main/docs/decisions/0029-a-repo-can-run-mutation-testing-in-check.md)).
* **JUnit's `fail(...)` counts as the test's assertion**, as in a test that fails in the catch of what it checks ([record 0028](https://github.com/fiftiesHousewife/under-test-java-conventions/blob/main/docs/decisions/0028-junits-fail-counts-as-the-tests-assertion.md)).
* **A comment after a field, on the field's own line, fails Checkstyle**, as a comment above it already did ([record 0005](https://github.com/fiftiesHousewife/under-test-java-conventions/blob/main/docs/decisions/0005-comments-only-where-they-belong.md)).
* **Fixed:** when `underTest.codeStyleExcludes` leaves out every class of a source set, its SpotBugs task skips, where SpotBugs used to print its usage and fail.
* **Record 0027** now holds the test libraries' assertion calls added in 0.2.0, and record 0004 is back as it was accepted.

Moving from 0.2.0: a field with a comment at the end of its line now fails the build. Everything else is new settings, off by default, or fixes.
