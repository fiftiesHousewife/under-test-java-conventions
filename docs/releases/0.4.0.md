## What changed since 0.3.0

* **A test run ends in one line.** `test` and `integrationTest` end with "All 7 tests passed." or similar, and a failure fails the build with "3 of 7 tests failed. Report: build/reports/tests/test/index.html", the path from the project's folder. In a quiet build (`--quiet`) nothing shows a person's home folder; at Gradle's usual level, Gradle's own warning still names the report by its full path ([record 0032](https://github.com/fiftiesHousewife/under-test-java-conventions/blob/main/docs/decisions/0032-a-test-run-ends-in-one-line-naming-its-report-by-a-path-from-the-project.md)).
* **Integration tests are their own suite.** `src/integrationTest`, with the unit tests' libraries, run by `check`. In CI an integration test that didn't run fails the build, unless `underTest.integrationTestsMaySkip = true` ([record 0033](https://github.com/fiftiesHousewife/under-test-java-conventions/blob/main/docs/decisions/0033-integration-tests-are-their-own-suite-run-by-check-and-in-ci-none-may-skip.md)).
* **A test JVM with Mockito starts with Mockito's agent**, the repo's own `mockito-core`, so JDK 21 and later don't warn about an agent attached at run time ([record 0034](https://github.com/fiftiesHousewife/under-test-java-conventions/blob/main/docs/decisions/0034-a-test-jvm-with-mockito-starts-with-mockitos-agent.md)).
* **A method with `@Override` takes the parameters its supertype fixed**: the three-parameter limit no longer fails it ([record 0031](https://github.com/fiftiesHousewife/under-test-java-conventions/blob/main/docs/decisions/0031-a-method-overriding-another-takes-the-parameters-its-supertype-fixed.md)).

Moving from 0.3.0: a repo with its own `integrationTest` suite or source set removes it, as the plugin's has that name, and drops any Mockito agent set-up of its own. When tests fail, the failed task is now `testSummary` (or `integrationTestSummary`), not `test`. In CI, a skipped integration test now fails the build.
